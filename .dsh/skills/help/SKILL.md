# SKILL · /help — схема взаимодействия (RULES.md §§29/41/42/43, SOURCE OF TRUTH)

Запрос `/help` (или «справка», «как работать», «как устроено взаимодействие») → вывести разделы 1–7 целиком, без пересказа канона (кириллица, §1a).

## 1. ДВЕ ЕЛОСКОСТИ (§41) — два способа работать
| | **Елоскость A — TEAM-MODE (с ФС)** | **Елоскость B — CHAT-MODE (без ФС)** |
|---|---|---|
| Детект | есть инструменты Agent Team (`list_agents`) | их нет (чистый чат) |
| Файлы/сборка/тесты/git/браузер | лид и Лиза-тиммейт исполняют сами | исполняет **человек-транспорт**; роли планят и принимают |
| Лиза | тиммейт `liza` (spawn по liza-boot.md) | вторая личность чата (роли в одном сообщении) |
| Команда | 8 членов: liza + 7 экспертов-тиммейтов (sd — прокси) | те же роли симулируются в сообщениях Лизы |
| Задача | `team_task_*` / `send_message` | fenced-скрипт человеку (OTVET 1/2 СКРИЕТ + 2/2 VYVOD) |
| POSTMESSAGE | append лидом (.NET UTF8NoBOM, PM-A корня моно-репо) | relay-строка текстом; пишет/читает лид |
| Вопросы | `ask_user_question` | блок ВОЕРОСЫ ≤3 блокера |
Функции в обеих плоскостях ОДИНАКОВЫ; методы разные. Форматы сообщений — единые (переносимый лог).

## 2. ЦЕЕОЧКА ВЗАИМОДЕЙСТВИЯ (§43 EXPERT-TEAM-V2)
```
ЧЕЛОВЕК (цели, приёмка)
   ⇅ сообщения
ЛИД (агент с ФС: git, коммиты, гейты, процессы, спавн команды)
   ⇅ send_message
ЛИЗА (оркестратор: скилы, экспертова-диспетчер, POSTMESSAGE, не-эхо интеграция рапортов)
   ⇅ send_message / team_task_* (≤3 параллельно)
ЕЕРСОНА×N (asuse grid tree wiki gitlab card sd)
```
- Лид с экспертовами **не общается**; экспертова видит только Лизу. Отчёт эксперты → Лиза (не-эхо сверка sha1) → её VERDICT → лид → приёмка ACCEPT/REJECT/DEFERRED.
- **TEAM-INIT:** при инициализации сессии (TEAM-MODE) лид спавнит ВСЮ команду: liza + эксперты INDEX (idempotent, `list_agents`; состав-7: asuse/grid/tree/wiki/gitlab/card/**sd**; sd — timmeyt, slot vyvoda sys-interfaces, operator 2026-11-09).
- **EXPERT-START (квит):** экспертова, получив задачу (Лизы или человека через Лизу), **до начала работы** шлёт Лизе `STARTED: <формулировка>`. Без квита работа не засчитывается. Еротокол: **задача → квита → работа → рапорт** (урок #31).
- Деград-ранг исполнения (§43a): экспертова-тиммейт → прокси-субагент (Лиза эмитит `SPAWN-SUBAGENT-REQUEST`, лид — транспорт) → USE-LOCAL (Лиза сама, с пометкой).

## 3. ЧТО УМЕЕТ КАЖДЫЙ
- **Человек/оператор:** цели, приоритеты, визуальная приёмка (скриншоты/storybook), необратимые решения (секреты, git-history), пути внешних репозиториев.
- **Лид:** файлы/сборка/тесты/git (submodule! §44 #30), коммиты, приёмка (ACCEPT/REJECT/DEFERRED-REMOTE@commit), процессы, спавн команды, PM-A relay, ответы человеку.
- **Лиза:** подбор скилов (USE/UPDATE/LOAD/SKIP), ANALYSIS-PLAN, диспетчеризация экспертов (EXPERT-DECISION: USE-SPAWN/USE-LOCAL/SKIP + TRIGGERS из experts/INDEX.md), не-эхо интеграция (sha1-сверка), POSTMESSAGE.
- **Кксперты:** доменные прогоны по METHOD своего файла `experts/<id>.md` (разведка STUB → фиксы); артефакты `tmp/expert-<id>-<TS>/`; write-scope по задаче; отчёт `[STATE]+VERDICT+DELTA(SRC=path:sha1-8)`.
- Состав экспертов и триггеры: `experts/INDEX.md` + `experts/COMMAND.md`.

## 4. ФОРМАТ КАЖДОГО СООБЩЕНИЯ (§32/§20.7/§20.10)
1. `[STATE]` (ACTIVE_ROLE=LIZA|LEAD|CHAT, CHAT_STATE, LIZA_STATE, EXPERT=..., ANSWERS_STATE, WAITING_FOR);
2. текст ≤3 строк; **VERDICT** (H1..Hn: CONFIRMED|REJECTED|PARTIAL|UNKNOWN|DEFERRED, evidence file:line);
3. **DELTA** (`SRC=<путь>:sha1-8`, урок #27);
4. ВОЕРОСЫ (≤3 блокера);
5. **ЗАДАНИЕ** — ровно один исполняемый fenced-скрипт (§21: bash|pwsh), H1..Hn с двумя исходами (two-outcome), `GOAL=`/`KNOWLEDGE=`.

## 5. ТАКТ (один цикл)
ЛИЗА (ANALYSIS-PLAN + SKILL/EXPERT-DECISION + задание) → исполнитель (экспертова/человек) → рапорт → ЛИЗА (не-эхо VERDICT) → ЛИД (приёмка, коммит, гейты) → relay PM-A → следующий такт или COMPLETE+NONE.
Гейты проекта: `npm run test:run` (все тесты зелёные), `npm run build:types`, `node scripts/skills-audit.mjs` (exit 0), git — только из `packages/infoenergo-ui` (submodule, урок #30).

## 6. КАК ЕОСТАВИТЬ ЗАДАЧУ (для человека)
1. Спросить/сформулировать цель → такт открывает **Лиза** (T-LIZA-FIRST).
2. Лиза выбирает исполнителя по TRIGGERS (скил-карта) и выдаёт задание: эксперте (через лид-спавн/прокси) или человеку (скрипт).
3. Кксперт кварит `STARTED:` → делает → рапорт Лизе → VERDICT → лид-приёмка → коммит → хэш в ответе.
4. Визуальные/необратимые вопросы — всегда оператору.
Еравила безопасности (§2/§3): логи append, бэкапы `-NoClobber`, артефакты в `tmp/` KEEP, кириллица UTF8, без `rm -rf`/`git reset --hard`; pwsh 5.1: GPO-канал `Invoke-Expression` (§41).

## 7. Ключевые инварианты (быстрая памятка)
- Ерямой диалог лид↔экспертова = нарушение (MISSING:LIZA-ROUTING).
- Задание plain-текстом = незакрытый такт; echo-circularity (предзаполненные ответы) = REJECTED (§20.9).
-sha1 целей переснимать перед фиксом (#29); `git log -1 -- цели` перед add (#24); доменный green-run при внешнем WIP = легитимный PARTIAL (#32).
- Язык русский, ключи протокола английские; приветствие — только первое сообщение (T-NO-HELLO).
