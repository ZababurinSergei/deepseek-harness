# SKILL · read-mode-task (universal)

<!-- created: 20261105-175000 -->
<!-- sources: RULES.md .dsh/skills/task-types/SKILL.md .dsh/skills/powershell-first/SKILL.md -->

## 0. Назначение
Правила генерации ЗАДАНИЙ, когда агент в read-only (песочница/запрет записей).
Инвариант: всё изменяемое (создание файлов, правки кода, остановка процессов) — выносится в задание и выполняется человеком в консоли.
Запрещено спрашивать «надо ли выполнить?» — задание выдаётся сразу, полным и самодостаточным.

## 1. Режим read-only: что выносится в задание
- Создание файлов (скрипты, конфиги, отчёты) -> задание (сохранение см. §3).
- Правки кода (даже surgical, даже 2 строки) -> задание; агент правит файлы ТОЛЬКО если sandbox их принимает без эскалации.
- Эскалации (workspace-write/danger-full-access) для чужих папок -> НЕ выбивать по одной: сразу скрипт в задание.
- Чтение/поиск/анализ/субагенты -> остаются агенту.
- Команды вида «запусти сервер/тест» -> задание (у агента нет рантайма пользователя).

## 2. Задание = проверка нескольких гипотез за один прогон (экономия времени)
Один прогон проверяет ВСЕ связанные гипотезы: CHECKS -> BACKUP -> LOGIC -> VERIFY -> VERDICT.
- Каждой гипотезе H1..Hn в VERDICT: status (DONE/CONFIRMED/REJECTED/UNKNOWN/PENDING-INTERPRET) + evidence (file:line/строка вывода) + priority.
- Гейты: первичные (синтаксис/порт/health) блокируют вторичные (пробы); при падении гейта — авто-восстановление из бэкапа + SKIP-строки, задание завершается корректно.
- В комментарии блока до запуска: список гипотез с evidence-источником (что именно смотреть в выводе).
- Интерпретация «не 0 и не 1» (HTTP-коды): печатать тело ответа ([body ...]), статусы трактовать в VERDICT с note.

## 3. Формы доставки задания (без зависаний консоли)
1. ПЕРВИЧНАЯ: агент пишет файл сам, если sandbox разрешает (tmp/ и .dsh/skills/ пользователем разрешены).
2. ВТОРИЧНАЯ (clipboard-save): только если запись агентом запрещена. Риск human-factor: в буфере оказывается НЕ тот текст (пример 20261105: в skills-файл попал предыдущий блок/лог, len~998). Правила: (а) явно указать в задании, какой блок чата копировать (границы «от строки X до строки Y»); (б) size-gate: saved len >= ожидаемого (порог в задании), иначе НЕ выполнять следующий шаг; (в) после сохранения — проверка маркеров/синтаксиса до использования файла.
3. ЗАПРЕЩЕНО: вставка многострочных блоков с { в интерактив -> continuation `>>` -> «задание зависло».
   Признак зависания: строки с `>>`. Лечение: Ctrl+C, затем форма 1/2.
4. Все команды в блоке — однострочные. Многострочная логика — только внутри .ps1.

## 4. Требования к скрипту задания (свод обязательных правил)
- ASCII-текст (кириллица в .ps1 ломает парсер PS 5.1; метки отчёта — английские).
- $ErrorActionPreference = Continue; без exit в середине; Log/Terminal/RAW/KEEP в tmp\<task>-<TS>\.
- BACKUP до правки: Copy-Item file $DIR\file.bak-<task>-<TS>.
- Правки якорем: проверить уникальность якоря (Select-String .Count == 1), вставить/заменить, затем node --check (js) / парсер (ps1); при fail — Copy-Item из бэкапа (VERDICT: REJECTED-RESTORED).
- КАРАНТИН вместо удаления: Move-Item в tmp\...\quarantine\; Remove запрещён (§3 правил чата).
- finally: копирование terminal.log в буфер (UTF-16LE через clip.exe, fallback Set-Clipboard, fallback «Ctrl+A/Ctrl+C»).
- [АКСИОМА]/[ГИПОТЕЗА] метки в отчёте; «Прислать: содержимое буфера (...)» последней строкой.

## 5. Свойство «не спрашивать разрешение на выполнение»
- Не формулировать «сказать выполнить?», «подтвердите» — задание с гипотезами выдаётся в том же сообщении, где принято решение.
- Опасные действия (остановка процессов, порты, прод-файлы) — не скрывать: предупреждение в комментарии блока (пример: «на G2 будет остановлен владелец 3107»), но задание выдаётся целиком.

## 6. Кейсы сессии 20261105 (проверено)
- continuation-hang: интерактивная вставка 100-строчного скрипта -> `>>`, ничего не выполнилось (кроме первых строк до первой незакрытой `{`). Лечение §3.3.
- clipboard-save-провал: в файл скилла попал предыдущий буфер (len=998) вместо нужного текста -> маркеры скилла отсутствуют, AUDIT_MISSING_MARKERS=1. Лечение: приоритет записи агентом (§3.1) + size-gate.
- якорь-ловушка 1: `[regex]::Replace(text,pattern,replacement,1)` — 4-й аргумент статического overload = RegexOptions, НЕ count -> замена во всех совпадениях (3 вставки MIN_KEEP_PATHS). Правильно: instance Regex.Replace(input, replacement, 1).
- якорь-ловушка 2: Regex.Replace ЗАМЕЩАЕТ совпадение — replacement обязан включать текст якоря, иначе он теряется (пропал `routes.forEach(` -> SyntaxError «Unexpected token ')'»).
- const-ловушка: `arr = arr.filter(...)` для `const arr` -> TypeError; мутация: `arr.splice(0, arr.length, ...arr.filter(...))`.
- порт из конфига: серверный порт из get_app_config; занят -> не подставлять свой: вывести «PORT <p> (from CONFIG) IS IN USE. FREE THE PORT» + exit(1); освобождение — владелец: `Get-NetTCPConnection -LocalPort <p> -State Listen` (PID -> Win32_Process path), остановить в задании.
- env-PORT игнорируется, если код берёт CONFIG.port (читать источник порта до предложения оверрайдов; оверрайды — только с явного решения пользователя).

## 7. Чек-лист генерации задания (быстрый)
1. Read-only? -> всё изменяемое в блок. 2. Гипотез >=2, гейты первичными. 3. Форма 1 (запись агентом) иначе форма 2 с size-gate. 4. Бэкап+карантин+KEEP. 5. node --check/парсер с авто-откатом. 6. Clipboard finally. 7. «Прислать: …» последней строкой. 8. Никаких вопросов «выполнить ли?».
