## [TASK-OUTPUT-RULES] 2026-11-07

### 1. USAGE в шапке каждого скрипта
Каждый fenced-скрипт начинается с:
```
# TRANSPORT: bash|pwsh
# USAGE: bash <этот-файл> [--preview|--apply]      (по умолчанию --preview)
# TASK: <одна строка>
```

### 2. Безопасный дефолт при неверном/пустом аргументе
- `MODE="${1:-}"`; `case` c веткой `""` и `*` → печатать `NOTE: ... → --preview`, НЕ `exit`.
- Запрещено: `exit 1` на usage до установки `trap`.
- `usage` печатается и скрипт продолжает в `--preview`.

### 3. Не терять вывод
- `trap _clip EXIT` ставится ДО любых `exit`.
- `exec > >(tee -a "$TERM_LOG") 2>&1` — после trap.
- При `exit` до trap терминал остаётся пустым — это баг, не норма.

### 4. Идемпотентность
- Каждая append-секция имеет маркер (`## [<MARK> <дата>]`); повторный запуск — `grep -qF "$MARK"` → skip.
- Бэкап перед записью: `cp -p f f.bak-<TS>`.

### 5. Кандидаты в preview/
- `--preview` пишет кандидатов в `tmp/<task>-<TS>/preview/`, целевые файлы не трогает.
- `--apply` пишет с бэкапами.

### 6. Финал задания — блок ВОПРОСОВ
Между `=== ВОПРОСЫ (ответы обязательны) ===` и `=== КОНЕЦ ВОПРОСОВ ===`, не в скрипте.

### 7. Ошибки-антипаттерны (реальные поломки)
- `bash <скрипт>` без пути → `$0=/bin/bash`, `$1` пуст → `usage + exit` → вывод стёрт. Фикс: дефолт `--preview`, не падать.
- `set -e` + `grep` без совпадений → скрипт умирает. Фикс: `set +e` + `${1:-}`.
