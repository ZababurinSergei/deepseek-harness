## 0. Когда использовать
Работа с компонентом `AiDataTable` пакета `@infoenergo/infoenergo-ui` (ROOT=packages/infoenergo-ui): подключение таблицы в приложение-потребитель, настройка колонок/редакторов/тулбара, режимы editable / tree / lazyLoad / master-detail, контракты эндпоинтов get/set/userChanges/userSettings/userData/export, отладка поведения и правки composable'ов в src/.

## 1. Компонент
- `AiDataTable` — обёртка над `NDataTable` (naive-ui) с тулбаром, футером, фильтрованием/сортировкой в заголовках, группировкой, редакторами ячеек, сохранением настроек, подкачкой, master-detail, деревом (`isTree`). Полная документация: `src/components/ui/AiDataTable/stories/description/AiDataTable.mdx` (+ Tree.mdx), примеры в `src/components/ui/AiDataTable/examples/`.
- Импорт компонента: `export { default as AiDataTable } from '@/components/ui/AiDataTable/AiDataTable.vue'` — `src/components/ui/index.ts:5`; vite-либ entry `src/index.ts` (vite.config.ts:18).
- Композиция в `AiDataTable.vue`: useVirtualScroll → useDataState → useColumnsConfig → useTreeRows → useLoadParams → useGrouping → useTableState → useTreeExpand → useTreeCutPut → useTreeSearch → useExportAdapter → useRowContextMenu → useToolbarConfig (AiDataTable.vue:100–443).

## 2. Props (TableProps, src/components/ui/AiDataTable/types.ts:105–170)
- Обязательные: `columns: UserOnlyColumn[]`, `api: { get: string; set?: string }` — строковые эндпоинты, НЕ функции.
- Ключ/идентичность: `keyExpr` (дефолт `'id'`, defaults.ts:7), `viewId` — id настроек и ключ кэша (detail: `viewId:parentRowKey`).
- Режимы: `isEditable`, `isTree` + `tree: TreeConfig` (`parentIdExpr` дефолт `'parent_id'`, `hasChildrenExpr` дефолт `'has_item'`, `remoteChildren` — подкачка детей; аргумент запроса `keyParentValue`, defaults.ts:10–16), `lazyLoad` + `pageSize` (дефолт 100), `selectionMode` (дефолт `'multiple'`), `masterDetailHeight` (400), `cellHeight` (34).
- Прочее: `showToolbar` (true), `showFooter` (true), `title`, `args { get, set }`, `config: Partial<DataTableProps>` (сливаются поверх внутренних, defaults.ts:46–50), `toolbarItems`, `contextMenu`, `autoLoadData` (true), `autoFocus` (true), `disableFocusedRowPersistence` (false), `disableAutoSaveUserData` (false).
- `UserOnlyColumn` (types.ts:15–38): `dataField` (ключ naive-ui), `caption`, `dataType` (DataType = `string|number|date|datetime|boolean` (interfaces/common.ts:17); `selector|popover|modal` = EditorType (:20), FieldType = union (:23); размеры/выравнивание по типу defaults.ts:60–95; если не задан — авто-вывод из значений, §5 `dataTypeInference`), `displayField`, `allowEditing`, `editor` (`selector|popover|modal`), `component`, `children` (иерархические заголовки), `visible`, `showInColumnChooser`, `cellTemplate` (слот ячейки).

## 5. Composable'ы (src/composables/AiDataTable/)
- `useDataState(tableProps, keyExpr, emitUserData)` — фасад состояния данных: `data loading isDirty updateRow isModified getValidationErrorMessage initData loadData saveData setData createRow createSiblingRow createChildRow copyRow removeRows loadChildren getVirtualScrollTools restoreUserData getDataRowIndexByKey` (:22–255). Оборачивает useChangesTracker + useDataStore + useUserData.
- `useDataStore(tableProps, keyExpr, rowChangesByRowKey, newRows, data)` — сетевой слой: `getData` через `tableApi.data(getApi, args)`, `saveModifiedData`, `insertNewRow/insertSiblingRow/insertChildRow/createCopiedRow/deleteRows`, `updateRowField` (с серверной валидацией `validationErrors`), `buildGridChanges/applyGridChanges`, `loadChildren` + `getVirtualScrollTools` (lazyLoad, `hasNextPage`/`loadNextPage`).
- `useChangesTracker` — `isDirty isModified trackInsert/trackUpdate/trackDelete resetChanges getUpdatedRowKeys getInsertedRowKeys`; новые строки: `isNewRow: true` + `__tempRowKey` (rowUtils.ts:8–11).
- `useUserData(tableProps, buildGridChanges, emitUserData)` — черновик правок на сервере по `viewId` (автосейв debounce 1000 мс, useUserData.ts:6); без `viewId` — console.error, черновик не сохраняется.
- `useColumnsConfig(..., slots?, getRows?)` — сборка колонок (defaults по dataType), `visibleColumns allBaseColumns columnsChooser setColumnsVisibility reorderColumns (перемещение только внутри группы, :162–164) getColumnsSettings applyColumnsSettings updateColumnWidth rebuildColumns filterRows loadFilter searchValue searchTerm (debounce 500 мс) filterTree`; фильтры заголовков через useFilterState + filterOperations (applyString/Number/Date, compileFilterTree, `BACKEND_FILTER_OPERATORS` contains/startswith/…/`<=`, defaults.ts:1–12). **Авто-вывод типа (57aa8e2):** `resolvedDataType = dataType ?? inferDataType(первые 50 значений колонки) ?? DEFAULT_DATA_TYPE` (:291–294) применяется в 7 точках (getDefaultColumnConfig, createFieldRenderer, makeSorter, updateFilterState, HeaderCell props, applyFilterSelection, setFilterInput); 8-й параметр `getRows` подаётся из AiDataTable.vue:139 как `() => data`; колонки пересобираются ОДИН раз при первой загрузке строк 0→N (watch :402–410), N→M (страницы lazyLoad) — не пересобираются (иначе сброс фильтров заголовков).
- `dataTypeInference` — `inferDataType(values): DataType | undefined` (dataTypeInference.ts:28–66): сэмпл = первые `DATA_TYPE_INFERENCE_SAMPLE=50` непустых значений, порог **100%** (одно нераспознанное → undefined → колонка строковая = обратная совместимость); приоритет boolean → Date (полночь→date, иначе datetime) → RU `dd.MM.yyyy(, HH:mm:ss)` → ISO локальные → микс RU+ISO → datetime; СОЗНАТЕЛЬНО не выводит: `number` из строк (ИНН/телефоны/счета), даты из чисел (epoch-двусмысленность), boolean из строк; тесты tests/dataTypeInference.test.ts.
- `useTableState(...)` — `focusedRowKey/Data expandedRowKeys checkedRowKeys data tableSettings tableResetKey resetState isFocusedRow isCheckedRow` + userSettings (useUserSettings: `getUserSettings setUserSettings scheduleUserSettingsSave cancelScheduledSave`).
- `useTableCache / useLruCache` — LRU кэш состояний по `viewId` (max 32, evict только «чистые»: rowChangesByRowKey.size=0 && newRows.size=0, useTableCache.ts:6–18); кэш подключается через `useCache` вкладок (useTabs/useTabCache).
- `useLoadParams(filter, reload?)` — `loadParams = { filter?, sort? }` + `setSortState`; reload debounce 500 мс, последовательный (RELOAD_DEBOUNCE_MS, defaults.ts:25).
- `useGrouping` — группировка строк/колонок (`isGroupRow __isGroupRow`, groupingUtils.ts:8); `useExportAdapter` — экспорт Excel через `tableApi.export` (mdx exportAllData/exportSelectedData); `useToolbarConfig` — элементы `refresh save column-chooser export settings add delete copy search` + tree-id (toolbar/types.ts:2–19).
- Tree: `useTreeRows` (`isRemoteChildren displayRows`), `useTreeExpand`, `useTreeCutPut` (`cut/putSibling/putChild`), `useTreeSearch` (`findStart/findNext/findPrev`), `treeUtils.buildTreeFromParentId/collectTreeSearchMatches`; `useColumnHeaderDrag` (DnD MIME `application/x-ai-column-field`), `useRowContextMenu` (дефолт-опции `copy-row/delete-row`, defaults.ts:107–116).

## 6. Контракт потребителя (инициализация)
- `initGlobalSettings({ tableApi, cardApi })` ОБЯЗАТЕЛЕН до использования (обычно в `AiAppProviders`); валидация полей tableApi: `data`, `userChanges`, `userSettingsApi.get/set`, `userDataApi.get/set`, `export` — без любого из них throw (useGlobalSettings.ts:40–65; useGlobalSettings() бросает без инициализации :84–86).
- `api.get` — строковый эндпоинт; `args.get` — второй аргумент загрузки; тело save = `{ changes: { gridChanges } }` + `api.set` + `args.set`; userChanges: `{ viewId, changes: { gridChanges } }` (useUserData.ts:68–73).
- Ответ загрузка: `{ success, result?, data?, validationErrors? }` (useDataStore); для lazyLoad — `hasNextPage`, `pagination.count`.

## 7. Известные ограничения
- Сортировка двухрежимная: локально — компаратор `makeSorter` (common.ts; ru/ISO/numeric/Date, null в конец; тесты tests/useCommonSorter.test.ts 9 шт.); lazyLoad — `sorter:true` + `remote` и сервер **обязан** сортировать по `loadParams.sort=[{selector:dataField,desc}]` (useLoadParams.ts:15–26): example-сервер реализует `applyServerSort` (5ae7623), реальный meta-service/DAL — формуляр P2 в PM-A (relay takt7); строки `dd.MM.yyyy` на сервере = лексикографический дефект без нормализации.
- Сортировка × группировка (P5, t16): при `hasGrouping` в non-lazy naive-ui сортирует `data=tableData` ВМЕСТЕ с group-строками (`__isGroupRow` без dataField → `undefined`; `common.ts:39–41` = только строгий `null`, дальше по типу: number=NaN-перемешивание, string='undefined' в конец, boolean=false в начало) → структура групп ломается (STRUCT_BROKEN; демо FIX_OK: tmp/expert-grid-20261108-232025/demo.mjs:91A4A2C8). Правильный порядок = предсортировка rows ДО `buildGroupedRows` цепочкой [groupFields asc → saved sort] + отключение локального компаратора при hasGrouping (useGrouping.ts:13–27, groupingUtils.ts:77/:91–92). lazyLoad+grouping: порядок групп = первое появление значения в серверном порядке (groupingUtils.ts:23–33), не лексикографический при серверной сортировке только по sortField. Stories группировки нет — визуал = новая story (оператор).
- Группировка НЕ персистится в user settings (t20): `TableSettings` = {autoSaveMode, groupPanelVisible, focusedRow?, columns, checkedRowKeys} — `groupFields` отсутствует (types.ts:84–90); payload = tableSettingsSnapshot (useTableState.ts:92–98) → setUserSettings (useUserSettings.ts:49–64, дебаунс 500мс trailing, buildSettings на flush = финальное состояние); рестор applyTableSettings (:143–153) группировку не применяет; `groupFields = ref([])` (useGrouping.ts:24); DnD-действия не входят в триггер-набор автосейва (watch snapshot :185). Модель толерантности ресторa: unknown dataField → skip (applyColumnsSettings, useColumnsConfig.ts:232–244; :237 `if (!setting) continue`); groupableColumns = flattenBaseColumns(visibleColumns) (useGrouping.ts:30). [Закрыто фиксом e34c196: groupFields? в settings + restore + deep-watch.]
- Межгрупповая перестановка колонок (t22, закрыто `9611291`): drop чужой колонки принимался, затем `reorderBaseColumns` (columnUtils.ts:76–94) давал false → `message.warning` (useColumnsConfig.ts:162–164); теперь превентив: `dragSource{field,group}` per-инстанс в useColumnsConfig + `findGroupByDataField`, подсветка только при canDrop, drop в чужую группу = молчаливый no-op (warning = fallback programmatic), класс `--drag-disabled` (HeaderCell); drop на заголовок группы = warning-fallback (у группы нет dataField). Drop в GroupPanel = легальный emit('add') (своя цепочка :45–68). Сортировка колонок строго по dataField (makeSorter common.ts:33–59), displayField не участвует.
- displayField (t25, закрыто `d82e818`): опционален на входе (UserOnlyColumn types.ts:27), required внутри BaseColumn (дефолт =dataField в extendedColumn useColumnsConfig :295–307); потребление: `useDataStore.ts:30` fieldKeys (единственный потребитель — getNewRowData :52 шаблон новой строки; guard `!==dataField` = гигиена контракта), серверные фильтры field=displayField (buildFilterExpression :88/:114/:137, applyFilterTree :12 — КОНТРАКТ), рендер-пара (:250–266 displayValue/modifyData), локал-фильтр/поиск/группировка (:132/:152, columnUtils :36, :26/:35).
- Infinite scroll без totalCount (t27, закрыто `f6f6595`): вся геометрия `useVirtualScroll` строилась на `totalCount` (pagesCount :49, thumb :113–118, tooltip :159–178); ответ без totalCount → lastTotalCount=0 → мёртвый скролл. Теперь: `totalCount?: number` (interfaces/common.ts:100) → infinite-режим по null: isEnd = короткая страница (срез ответа до падинга useDataStore :463–471), геометрия по loadedPages, футер «≥N» (AiFooter prop isEnd), tooltip off; числовой 0 сохраняет числовой режим; useVirtualScroll.test (5) — впервые.
- lazyLoad+группировка (t29, закрыто кодом `3fd005e`): порядок групп = первое появление значения в серверном порядке (groupingUtils.ts:23–33) — клиентский код менять не нужно; клиент добавляет серверный префикс groupFields в loadParams.sort (useLoadParams опц. `groupSort {fields, selectorFor}`; selector = displayField ?? dataField; каскад по порядку массива). Example-сервер поддерживает многополевую сортировку каскадом (server.js applyServerSort :341–352); meta-service = Q6-PROTOCOL-TICKET (P2 закрыт его объёмом, 30af99b).
- Кэш store между табами (t31): `AiTabs/useTabCache.ts` WeakMap<tab-объект, LRU32 store>; `initData` при cache-hit делает ранний return (useDataState.ts:73–76) → повторное открытие таба показывает stale; **consumer-контракт обновления = `forceRefreshData()` (initData НЕ экспонирован)**; fromCache-гард бережёт черновик dirty-таба (не снимать); опц. проп refreshOnMount (P2 план).
- `useDataStore` читает `tableProps.api.get` без guard (:49) → TypeError при `api: undefined`; `api` обязателен в типе.
- `useAiGrid` УДАЛЁН из src (grep useAiGrid src/**/*.ts = not_found; остались только `.bak`), экспорта из пакета нет → скил `use-ai-grid` = foreign-context/устаревший.
- Без `viewId` не работают: черновик user-data и пользовательские настройки (console.error, useUserData.ts:29–36).
- `reorderColumns` — колонку можно перемещать только внутри своей группы (warning в UI, useColumnsConfig.ts:162–164).
- `loadData` без `isForce` при `isDirty` открывает диалог «Сохранить изменения?» (Да/Нет/Отмена) — useDataState.ts:96–116.
- LRU-кэш (32) эвиктит только чистые состояния; при переполнении с грязными состояние не сохраняется.
- `user-data-change` эмитится только при `disableAutoSaveUserData: true`; без него события нет (mdx:41).
- TS-тип-запись: `npm run build:types` (vue-tsc -p tsconfig.build.json, emitDeclarationOnly→dist/types) исключает `src/index.ts`/`components/ui/index.ts`/tests/stories/examples (tsconfig.build.json:4–15); entry дистрибутива — `src/index.ts` (vite.config.ts:18), а `types` entry пакета = `dist/types/public-api.d.ts` (package.json) — типы AiDataTable в нём отсутствуют.
- `useVirtualScroll` экспортирует только `useVirtualScroll()` (:23) — tools подают `getVirtualScrollTools`/`hasNextPage`/`loadNextPage`.
- Тесты компонента мокают useDataState/useColumnsConfig (AiDataTable.test.ts:19–50) — интеграция с сетью проверяется в example/, не в юнит-тестах пакета.
